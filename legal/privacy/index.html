Privacy Policy

This notice explains the current data practices for this unofficial fan site. It is not legal advice. We update it when authentication, storage, analytics, payments, or other material data practices change.

Last updated: October 3, 2026

What this site stores

Core game catalog and published builds live in our Supabase project (database + related storage). We do not run third-party ads on these pages. Accounts use Discord OAuth via Supabase Auth (no email/password signup on this site).

  • Builds — title, tags, board placements, route notes, optional video link, moderation flags, author link. Event entries stay visible only to their author until that event's gallery opens (when a scored event ends, or when voting starts). Until then they are not on the public builds feed
  • Profiles — Discord user id, display name, Discord avatar URL, optional public equipped sim look (equipped_avatar), optional cosmetic grants, public coin balance (coins, for a future site marketplace), optional bound vote key, owner flag (for site admins), membership fields (plan, founding slot, premium_until, Stripe customer id when applicable), and a recent Discord-server verification time while Private access is enabled. Access, role, grant, and membership values are recorded by our server rather than accepted from browser profile edits.
  • Votes — anonymous voter_key in local storage + server vote rows; bound to your profile after Discord sign-in when possible
  • Local drafts — create-page drafts may stay in your browser (localStorage) until you submit or clear them
  • Combat sandbox — dummy fights on /sim/ run in your browser. Fight results stay local unless you send an issue report (see below). The page may keep a mode preference in localStorage (bpb-sim-mode)
  • Page visits — a daily count of which public pages were opened (home, items, a build guide, and so on). We do not store your account, IP address, or the query string. A browser session is counted once per page. Admin pages are not counted. Only site owners can see the totals
  • Membership totals — once a day we store how many accounts, paid Premium members, and founding members exist, plus monthly revenue estimated as paid Premium times $3. No names and no card data. Only site owners can see that chart

Paid membership / Stripe

Optional Premium membership is billed through Stripe (Checkout and Customer Portal). Card numbers and full payment details are handled by Stripe; we do not store raw card data on this site. On your profile we may store membership status (plan), an optional access end time (premium_until), and a Stripe customer id so we can open the billing portal and apply webhook updates.

  • Founding members — the first eligible Discord sign-ins may receive lifetime Premium as a site entitlement (not a Stripe charge). That grant is separate from paid subscriptions.
  • Retention — membership fields stay with your profile while the account exists; canceling a paid plan updates status via Stripe webhooks
  • Deletion — contact us via Discord or YouTube to request removal of profile / billing-linked membership data (Stripe may retain its own records per their policy)

Discord accounts

Signing in with Discord returns to the approved BPB Builds site URL where the flow began, creates a Supabase session, and creates a public profile page at /u/{discord_id}/. We store the Discord snowflake, display name, and avatar URL (plus an optional public equipped look for the combat sim) so we can credit builds and show your persona. Display name and Discord avatar sync from Discord; the equipped look is separate and only changes when you set it. Submitting a build requires a signed-in Discord session. You can sign out from the site nav. After sign-in, our Discord bot checks whether that account is in the community server. When site owners enable private access, that membership result is used to allow or deny access to the site UI and Supabase-backed app data; otherwise, a non-member may be offered an invite. If the account is in the server, your site plan (free, Premium, or founding) is mirrored to a Discord role. In that server the bot keeps the nickname you set and adds how many builds you have uploaded. When a build is public on the site, the bot posts it in the server builds forum (title, class, author, link, and a picture of the board). The bot does not change your site plan. Deletion requests for a profile or published builds: contact us via Discord or YouTube (see Contact).

Blob cosmetic submissions

The Submit cosmetic form on your profile Blob / Inventory tabs may collect a cosmetic name, equip slot, artist credit, notes, and an image file. The early stub does not upload to our servers yet (it only acknowledges the form locally). When a review pipeline ships, submissions will be stored for moderation and possible display; contact us via Discord or YouTube to request deletion.

Site owners may also upload official cosmetic artwork from the private admin page. Those files are stored in Supabase Storage with catalog metadata; an upload remains an owner-only draft until it is published, after which its image and catalog fields are public wardrobe data.

Combat sandbox issue reports

If you use Report issue on /sim/, we store the description you type plus a frozen copy of session facts we show on that form (seed, signed-in display name or “Guest”, your board, opponent, script coverage, and permalink). You cannot edit those facts; we keep them so we can reproduce the fight. Signed-in reports may also store your profile id. Reports are reviewed by site owners on a private admin page — they are not public.

  • Retention — kept until we resolve or delete the report
  • Deletion — contact us via Discord or YouTube to request removal

Steam history.db uploads

If you attach a Steam history.db run in the creator, we may store run metadata needed to show a Real build and round scrubber — for example board layouts per round, win/loss markers, class/league display fields, and related item placements. We use this to power the site experience, not to sell your history. For an event, the site owner can download those stored runs as one history.db to open in the game while judging.

  • Retention — kept with the draft/build while the history remains attached
  • Clear / unlock — clearing run history on create removes the attached history from that draft (Real → Feasible)
  • Deletion requests — contact us via Discord or YouTube to request removal of a published build, attached history, or account profile data

Paused screenshot import

Screenshot-to-build reconstruction is paused for launch. The Create page does not accept backpack screenshots for processing, so this feature does not collect, upload, or store screenshot images.

  • No processing — image uploads and the optional cloud fallback are disabled
  • Existing builds — manual board edits and saved builds continue to work normally
  • Future change — this policy will be updated before screenshot processing is restored

Votes

Likes/dislikes use a key in your browser plus server-side vote records. Before sign-in the key is anonymous (bpb-voter-id). After Discord sign-in we bind that key to your profile when possible so votes follow your account across devices. Clearing site data before binding can create a new key.

Hosting & logs

The static site is hosted on GitHub Pages (and may sit behind a CDN). Standard hosting and database provider logs may exist for security and reliability.
